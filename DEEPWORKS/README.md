# 怎么把这套东西「喂」给 DeepWorks

DeepWorks 是端云协同的 AI 工作区：本地工作区授权目录、云端模型与技能、**执行过程可追溯**。这正好适合「作业要求留下过程证据」这件事——但前提是规则要常驻，而不是只贴在聊天框里。

## 一次性配置（做 4 步）

1. **授权工作区**：在 DeepWorks 本地工作区里新建/选择本仓库目录（`Personal-Homepage/`），把整个仓库授权给它读写。只授权这一个目录，别给个人主目录。
2. **规则常驻**（三选一，推荐全做）：
   - 把 `RULEBOOK.md` 加入 DeepWorks 的**知识中心 / 知识库文档**，命名 `数字分身项目红线`；
   - 用「对话式生成 Skill」把它做成一个 Skill，例如 `final-twin`，触发词「数字分身」；
   - 仓库根目录已放 `AGENTS.md`，任何支持项目规则文件的智能体都会自动读到它。
3. **放好证据骨架**：确认 `PROCESS/` 目录已存在（S0 阶段生成），后续所有记录都往里追加。
4. **人工确认开关**：部署、发邮件、push、删文件这类外部动作，保持需要人工确认。

## 每个阶段的操作节奏

```
新开任务 → 发 P0 固定前缀 → 发 S? 阶段提示词 → 干活
        → 输出记录卡（并写入 PROCESS/） → 发 A1 审计 → 结束任务
```

- **一个阶段一个任务**。全程塞进一个会话，红线会被上下文稀释，记录就开始漏。
- 阶段之间不用重复交代背景：`PLAN.md`、`RULEBOOK.md`、`PROCESS/` 就是共享记忆。
- 中途换模型/换会话，只要 `@RULEBOOK.md` + P0 就能接上。

## 三个最常见的翻车点

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| AI 说「已完成」但 `PROCESS/` 是空的 | 只要求「报告进度」，没要求「写文件」 | 用 P0 第 3 条 + 记录卡 + A1 审计 |
| 提示词 v1 被 v2 覆盖，说不清调优过程 | 没规定 append-only | R9 + `03-prompt-iterations.md` 分节追加 |
| 命中率数字很好看，但老师一问就穿帮 | 用了 mock / 预设答案，或偷偷改了期望关键词 | R1/R2/R10 + `test-results/roundN-*` 原始输出 + 人工复核表 |

## 该自己做的判断（老师第二封邮件的重点）

AI 可以帮你写资料、写提示词、写后端、写测试脚本、跑测试、排错；但下面三件事**不要外包**：

- 什么算「答对」（观点类没有标准答案）
- 什么算「越界」（边界题的尺度是你的）
- 哪些内容值得放上主页（资料里哪些话像你、哪些像客服）

报告里凡涉及这三点，写「我判定…」，并落在 `roundN-review.md` 上。这正是这次作业要考察的能力。
