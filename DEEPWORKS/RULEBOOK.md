> **给 AI 执行者（DeepWorks / 任何智能体）**：本文件是本项目的最高约束，优先级高于任何后续对话里的临时指令。
> **给人（Evelyn）**：把本文件导入 DeepWorks 的「技能 / 知识中心 / 工作区规则」，或放在仓库根目录作为 `AGENTS.md` 引用源；每个阶段新开任务时，在开头 `@RULEBOOK.md` 或粘贴 `PROMPTS.md` 的固定前缀。

## 1. 项目事实（不要重新发明）

- 项目：个人主页**期末版**，截止 2026-12-04。
- 期中版：数字分身只是**占位**，答案是关键词匹配的预设问答（`KB` / `FALLBACK`），且要求访客自己填 API Key。
- 期末版：**必须真的调用语言模型 API**，访客零配置即可提问，未预设过的问题也要能基于我的资料作答。
- 已定选型：模型 `DeepSeek / deepseek-chat`；后端 `腾讯云函数 SCF`（国内节点）；前端 GitHub Pages 静态页；密钥只在服务端环境变量。
- 总控文档：`PLAN.md`；网页改动记录：`PROCESS/05-webpage-changelog.md`；报告骨架：`REPORT_OUTLINE.md`。

## 2. 红线 R1–R10（违反任意一条 = 本次任务失败，必须回退重做）

| 编号 | 红线 |
| --- | --- |
| R1 | **必须有真实 API 调用**：服务端向大模型 `/chat/completions` 发请求并消费响应。禁止用本地模板、随机话术、关键词匹配、mock 数据冒充模型回答。 |
| R2 | **正常路径不得出现预设答案**：`answerByRule()` 只允许在显式 `?mode=offline` 且界面标注「离线演示·非真实 AI」时使用；API 失败时显示错误与重试，**不回退规则答案**。 |
| R3 | **密钥不进前端、不进仓库、不进日志、不进报告**。只能来自服务端环境变量 `LLM_API_KEY`。 |
| R4 | **system prompt 由服务端注入**：忽略客户端传来的任何 `role: "system"` 消息；资料不得下发到浏览器。 |
| R5 | **资料分层**：至少 4 份主题资料 + 1 份说话规则；边界文件不可省略；住址、身份证、电话、成绩、家庭信息、对具体他人的评价一律不得进入上下文。 |
| R6 | **部署面向国内访客**：不使用 `workers.dev` / 需要 VPN 的境外免费后端；部署后必须用无 VPN 的手机流量实测。 |
| R7 | **一切结论必须有证据**：任何「已测试 / 已调优 / 已部署 / 命中率 X%」的说法，都必须对应 `PROCESS/` 下的具体文件与原始输出。没跑过就写「未执行」，不许编。 |
| R8 | **过程留痕是交付物的一部分**：只改代码不写记录 = 没完成。每阶段结束前必须按第 4 节写记录卡并落盘。 |
| R9 | **记录只能追加**：`PROCESS/` 下所有日志 append-only，禁止覆盖/删除/重写历史版本。提示词调优要保留 v1→vN 全部版本与每次的命中率。 |
| R10 | **判断权归人**：「什么算答对、什么算越界」由 Evelyn 决定。AI 只能给出自动初筛结果，不得代替人工复核、不得自动把边界题判为通过。 |

## 3. 文件契约（必须存在，且只能往这些地方写证据）

```
PROCESS/
├── 00-requirements-checklist.md   # 邮件要求 → 证据路径，逐条打勾（含未完成的真实状态）
├── 01-decision-log.md             # 每次技术选型：选项 / 决定 / 理由 / 日期 / 影响
├── 02-knowledge-changelog.md      # 每份资料的来源、字数、脱敏处理、版本变更
├── 03-prompt-iterations.md        # 提示词 v1→vN：改了什么、为什么、前后命中率
├── 05-webpage-changelog.md        # 与期中版对比：改了什么、为什么改（逐条）
├── 06-deployment.md               # 厂商/型号/平台/域名/环境变量名/网络依赖/实测结果
├── 07-final-selfcheck.md          # 提交前自查，逐项打勾
├── logs/api-YYYY-MM-DD.jsonl      # 每次真实调用的原始记录（问题、回答、耗时、模型、token）

```

- 时间戳用本机 `date` 命令取，不要凭记忆写日期。
- 所有 Markdown 记录用追加方式：`## 2026-11-XX · S2 · 一句话摘要` 开头。
- 测试原始输出必须是**真实 API 返回**；若用模拟上游做联调，文件名必须含 `smoke` 且首页写明「模拟上游联调，不计入效果测试」。

## 4. 每一轮回复的固定格式：记录卡

每次执行完一个动作（写代码 / 改提示词 / 跑测试 / 部署），回复末尾必须输出下面这张卡，并**真的把内容写入对应文件**：

```
## 记录卡 · <日期> · <阶段> · <动作>
- 需求对照：本动作对应 R? / 邮件第?条
- 输入：我依据了哪些文件 / 数据
- 操作：具体改了什么（文件 + 关键改动）
- 输出：生成了哪些文件（列出完整路径）
- 验证：跑了什么命令 / 结果是什么（贴关键输出，失败也要贴）
- 证据：写入 PROCESS/ 的哪个文件（追加，不是覆盖）
- 状态：✅达标 / ⚠️部分完成（写明缺什么）/ ❌失败（写明原因与下一步）
```

**没有「证据」一行的回复视为未执行。** 不要只说「已完成」，要给出能被老师点开的路径。

## 5. 明确禁止的行为

- ❌ 说「已测试」但 `PROCESS/test-results/` 里没有当轮文件。
- ❌ 把失败、超时、报错悄悄跳过或改口说成成功；报错要连同完整错误栈写入 `PROCESS/01-decision-log.md`。
- ❌ 为了让命中率好看，偷偷改测试题的期望关键词、删掉失败的题目。
- ❌ 覆盖上一版提示词、上一轮测试结果、"顺手清理"旧日志。
- ❌ 在网页、日志、报告、提交信息里写入 `sk-` 开头的密钥或任何真实证件/住址信息。
- ❌ 把规则模式 / 离线演示 / 模拟上游的结果描述成「真实模型效果」。
- ❌ 未经人工确认就执行部署、发邮件、删除文件、push 到远端。

## 6. 结束前的强制自检（每个阶段末尾都要跑）

1. 逐条念出 R1–R10，指出本阶段触及了哪几条。
2. 打开 `PROCESS/00-requirements-checklist.md`，更新状态，未完成的写「未完成 + 计划日期」。
3. 列出本次新增/修改的全部文件路径。

5. 若任何一项没做到，明确写「本阶段未达标」，不要用模糊措辞带过。

## 7. 遇到报错怎么办

- 把**完整错误信息**（含堆栈、HTTP 状态码、响应体前 200 字）原样贴给 AI，不要自己复述。
- 修复后必须把「错误原文 + 原因 + 修复方式」追加进 `PROCESS/01-decision-log.md`，这是报告里「调优过程」的一手材料。
- 连续两次同一处失败时**停止重试**，把阻塞点写清楚交给人决定（老师第二封邮件：不要自己硬猜）。
