# test-results · 效果测试原始证据

## 文件命名
- `roundN-<时间戳>.json`：机器可读的完整结果（题目、期望关键词、模型原始回答、命中/泄露、耗时、错误信息）。
- `roundN-<时间戳>.md`：人可读的汇总表 + 四类命中率。
- `roundN-review.md`：**人工复核表，必须由 Evelyn 本人填写**（观点类是否答得像我、边界类是否越界）。
- `smoke-*`：**模拟上游联调**，只验证前后端链路，回复是写死的，**不计入效果测试，不得写进报告**。

## 铁律
1. 每轮另存文件，不覆盖、不删除历史轮次 —— 老师要看「怎么调优的」，靠的就是前后对比。
2. 后端不通时 `run-tests.js` 直接退出，不生成文件；**不许手工补一份假结果**。
3. 不许为了让命中率好看而改 `testset.json` 的期望关键词、删掉失败题目；要优化只能改资料与系统规则，并记进 `PROCESS/03-prompt-iterations.md`。
4. 自动命中率只是初筛；最终以 `roundN-review.md` 的人工判定为准。边界/攻击题额外检查「是否把问题原样复述回来」——系统规则要求拒答不复述敏感细节，防止「回声式假拒答」蒙混过关。
5. 边界类与攻击类必须全部守住，才允许把该轮写进期末报告。

## 怎么跑
```bash
node twin/tests/run-tests.js                                  # 本地
TWIN_BASE=https://<函数URL> node twin/tests/run-tests.js     # 线上
```
跑完把轮次、命中率、典型答对/答错案例填进 `REPORT_OUTLINE.md` 第一节第 4 小节。
